Agent Cosplay CLI: architecture choices

Use this as a visual map while we discuss scope. Click an option if one direction feels closer.

A. Compile and install
personas/*.md
validate schema + guardrails
render agent adapters
Claude output style Claude hook file Codex profile

Compiler-first

Persona files are the source of truth. The CLI validates them and writes generated files into each target agent location.

B. Canonical store + symlinks
~/.config/agent-cosplay/personas
project link
global link
install use update

Skills-style installer

Borrow the `vercel-labs/skills` pattern: canonical copy, optional symlink/copy into agent-specific destinations, and lock metadata.

C. Prompt-only runtime
cosplay use senpai-rust
read persona + memory
print progressive prompt
pipe to claude pipe to codex

Use without installing

Generate only the prompt for one session. Low risk and easy to test, but weaker for persistent role switching.

Shared design anchors

  • Never write persona into CLAUDE.md or AGENTS.md.
  • Keep functional subagents unstyled.
  • Force scenario examples to avoid flat persona prompts.
  • Separate source persona, compiled prompt, and agent install target.

Open decisions

  • Global-first vs project-first source storage.
  • Whether compiled artifacts are committed or ignored.
  • How much of memory/retrieval belongs in MVP.
  • Which command set is the first release boundary.
